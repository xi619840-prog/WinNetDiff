## F5 通用宿主關聯

新增 `analysis/ownership.py`，不使用廠商名稱作為納入關聯的必要條件。以 NDIS 的精確 Service／CoServices、服務及驅動執行狀態、登錄映像路徑、安裝目錄邊界及已驗證簽章建立具來源的節點／邊。安裝目錄不能是磁碟根目錄或共用系統容器；路徑前綴相似不等於同一目錄。已驗證簽署者與應用程式 Publisher 相同只列為 PossibleHosts，不宣稱產品歸屬。這些可能宿主也會保護原有無 NDIS 的 WFP／共享 SDK 候選，避免新的通用關聯與舊規則互相抵消。

圖中分開呈現 owner_installed、owner_possible、owner_unknown、host_not_observed、inventory_incomplete 與有具體矛盾的 orphan_evidence。只有完整清單、獨立 Running、活動 NDIS 精確關聯及缺少服務登錄／執行中映像缺失等具體矛盾，才能提供通用 E3 交叉佐證。完整卸載清單沒找到產品、公司名相同、簽章有效或未知歸屬均不能單獨證明故障。分級時從原始盤點重建圖，不採信輸入的 EligibleCorroboration 標籤。

WFP XML 串流摘要新增與廠商無關的 provider→service、callout→provider、filter→callout 明確鍵關聯。命名空間、重複鍵、嵌入描述中的假 serviceName、有界記錄及未觀察到的宿主都有處理。DTD 在任何編碼／位置均拒絕，包含 UTF-16 與長註解之後。XML 上限 128 MiB，保留最多 2048 個結構記錄，圖另限制應用程式、服務及邊數；截斷不得提供缺失證據。

CLI `--wfp-input` 或 GUI「匯入 WFP 關聯資料」讀取既有檔案。匯入資料明確標為歷史快照，不證明目前 WFP 過濾器正在作用，也不能單靠它升級 E3。沒有自動要求 UAC 或變更 WFP。WFP 物件鍵、圖的識別碼與連線端點在預設匯出中使用 HMAC 假名。

## F6 企業代理路徑診斷

新增 `probes/proxy_path.py`。一般診斷先產生不發送代理測試流量的路徑計畫，分開處理 WinINET、WinHTTP 預設設定與程序／儲存的使用者、機器環境變數。WinHTTP 透過唯讀原生 API 取得結構化 proxy／bypass，不依賴本地化 netsh 文字解析。預設設定不代表目前應用程式 session；PAC／WPAD 保持未解析，不下載或執行。

旁路支援有邊界的網域後綴、Windows 萬用字元、<local>、埠與 IP/CIDR 診斷比對。不同應用程式的 NO_PROXY 語義仍可能不同；沒有把設定值當成已證實的應用程式路徑。儲存但未被程序採用的環境變數不自動測試。HTTPS／SOCKS 代理明確列為不支援，不降級為 HTTP。配置中的帳號／密碼不傳給探針。

代理路徑實測需明確操作 GUI 按鈕確認，或 CLI 同時指定 `--proxy-paths --confirm-proxy-paths`。離線模式拒絕。每次最多兩個不重複的靜態 HTTP 代理，對第一個測試網域發送 CONNECT、驗證目標 TLS、HEAD。上限為每階段 3 秒、單代理整體 12 秒；取消與整體期限獨立。沒有 Proxy-Authorization、預設認證、NTLM／Kerberos 自動登入或任何系統設定寫入。

407 是需要驗證，403 是政策拒絕，CONNECT、DNS、TCP、TLS 憑證及 HTTP 狀態各自保留。代理可能代為解析目標，因此明確記錄 target_ip_observed=false；代理與直連之間不比較延遲或合併 E2／E3，也不宣稱同一路由或同一 IP。新結構中的代理 DNS 名稱與 WinHTTP 設定字串在預設匯出中假名化。既有任意原始代理文字仍需分享前檢查，精簡診斷卡仍只使用固定欄位白名單。

## F7 同 IP 重試

預設 `--retry-mode same-ip`。每個 host×family 在該次 DNS 結果中選定第一個完整 sockaddr，所有重試重用它；IPv6 scope／port 不被重建或遺失。SNI 仍為原始網域，每次嘗試仍只有一條 TCP→TLS→HTTP 連線，DNS 其餘答案與每次嘗試位址都保留。沒有暗中切換至另一個 CDN 位址。

需要檢查其他 DNS 位址時可選 `--retry-mode rotate`，或取消 GUI「固定同一 IP 重試」。選項會保留於語言切換、設定、重新驗證與 UAC 參數。retry_mode 同時記入 scan_options 與每次嘗試 context，所以不同模式不能湊成同一路徑的重複證據，前後修復驗證也會拒絕不同參數。固定失敗的單一 IP 不代表該網域所有位址失敗。

## 測試與實際證據

本輪 Windows 基線 398/398。新增 60 項 F5–F7 與 GUI 生命週期回歸，最終完整套件 **458/458，無跳過**。舊旋轉位址測試改為明確指定 rotate，仍斷言第二個 DNS 答案被使用；舊 mock／參數清單新增 retry_mode 並保留原有取消、語言與嚴格相等檢查，沒有弱化獨立 14 項斷言。模組與生成單檔均有新功能對等測試。

`validate_f567_native.py` 在 Windows 使用真實 loopback TCP／TLS／HTTP，以及明確信任的暫時測試憑證，未安裝至系統信任庫。實測包含直接 TLS／HEAD、CONNECT→已驗證 TLS→204、407 Negotiate、403、未受信憑證拒絕、取消與整體期限。沒有發送認證。

同一動態埠的兩個 loopback 位址，第一個無服務，第二個提供已驗證 TLS。只有 DNS 答案注入為受控邊界，socket、TLS、HTTP、計時均真實。固定模式兩次相同 IP／相同失敗階段為 E2；輪替模式第一個失敗、第二個 HTTP 回應，每個 IP 只有一次，因此該失敗為 E1。Windows 可能在 300 ms 預算內呈現 TCP timeout，而非立即 refusal；保留實測類型，不改成 TLS 錯誤。

連續三語真機驗證曾抓到舊 Tk 視窗循環被新背景工作回收的錯誤。GUI 啟動時在所屬執行緒回收前次已銷毀視窗，新增獨立程序的強制 worker GC 回歸，且重跑真實三語盤點。失敗日誌保留為中途證據。沒有接管桌面或操作既有使用者視窗。

Windows 原生唯讀入口、GFM 渲染、三語隱藏 Tk、金鑰及既有安全測試另附指紋綁定摘要。單檔由模組生成，不直接修改；來源 ZIP 解壓後重新跑全套。最終詳細數字與 SHA-256 見交付 ACCEPTANCE.json，不以舊 2.2.0a2 或中途日誌作本輪驗收。

py -3 -m winnetdiff --cli --retry-mode rotate
